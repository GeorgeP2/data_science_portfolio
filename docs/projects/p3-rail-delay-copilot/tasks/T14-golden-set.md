# T14: Golden evaluation set

**Phase:** 4 Evaluation · **Estimate:** 4 h · **Depends on:** T05, T07

## Ask

Write ~150 golden questions across four types (SQL, rules, mixed, unanswerable), each with a
reference answer.

## Why

Every accuracy claim, the CI regression gate and the failure-mode analysis rest on this set.

## How

- SQL questions: reference SQL, run against DuckDB to store the expected result.
- Rules questions: reference answer + the DAPR/PGD/DAB section(s) that support it.
- Mixed: both. Unanswerable: out of scope or not in the data, expected behaviour = refuse.
- Stored as versioned JSONL with an `id`, `type` and `split` (dev vs held-out). Tag a small
  `ci` subset for cheap CI runs.
- Written by hand from the data and the rulebook; not generated by the model being evaluated.

## Plan

- [ ] Decide the mix per type (roughly balanced)
- [ ] Write SQL questions and reference SQL
- [ ] Write rules questions with sections
- [ ] Write mixed and unanswerable questions
- [ ] Mark dev / held-out / ci subsets

## Acceptance criteria

- [ ] ~150 questions, with counts per type reported
- [ ] Every SQL reference query executes and its result is stored
- [ ] Every rules reference cites sections that exist in the T07 index
- [ ] `ci` subset is small enough to run for well under £1 per build
